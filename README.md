### แท็บในชีท (สร้างเองตอนรัน `setup`)
- **บอท-ตั้งค่า** — 1 แถวต่อกลุ่ม/คน บอทเพิ่มแถวให้เองเมื่อถูกเชิญเข้ากลุ่มหรือมีคนทัก **ต้องเลือกซัพพลายเออร์และติ๊ก "เปิดใช้" เอง** ถึงจะเริ่มเก็บ
  - คอลัมน์ **ตอบรับในแชท** (reply ไม่นับโควต้า · แจ้งแค่ชนิด + เลขที่เอกสาร ไม่แจ้งยอดเงิน · เอกสารที่ส่งมาชุดเดียวกันรวมตอบเป็นข้อความเดียว): `ไม่ตอบ` = เงียบ · `เฉพาะเอกสารสำคัญ` = ตอบเมื่อเก็บ ใบกำกับภาษี/ใบเสร็จรับเงิน สำเร็จ กรณีอื่นเงียบ (กลุ่มซัพพลายเออร์) · `ทุกไฟล์` = รวมไฟล์ที่ไม่ใช่เอกสาร/ยังอ่านไม่เสร็จด้วย (ใช้ทดสอบ)
  - คอลัมน์ **รับแจ้งเตือน** (เฉพาะแถวชนิด user): ติ๊ก = บอท push เข้าแชทส่วนตัวของคนนั้นเมื่ออ่านเอกสารไม่ผ่านครบ 3 ครั้ง หรือดึงไฟล์จาก LINE ไม่สำเร็จ (นับโควต้า 1 ข้อความ/ครั้ง ไม่ส่งเข้ากลุ่ม) · เพดาน Gemini เต็ม (429/503) ไม่นับเป็นครั้งที่ผิดพลาด บอทลองใหม่เองทุกรอบ
- **บอท-คิว** — 1 แถวต่อไฟล์ที่รับมา: สถานะ `NEW` → `DONE` / `SKIP` (ไม่ใช่เอกสาร) / `ERR` (อ่านไม่ได้ 3 ครั้ง) พร้อมผลจับคู่และลิงก์ไฟล์
- **บอท-ข้อความ** — ข้อความในกลุ่ม (ตามที่ตั้งในคอลัมน์ "เก็บข้อความ")
- **ทะเบียนบิลซื้อ** — 1 แถวต่อบิล: ยอด จ่ายแล้วหรือยัง เลข/วันที่ใบกำกับ ได้ตัวจริง สถานะ รอตรวจ
- **ตามใบกำกับ** — รายการของวันนี้ (เขียนใหม่ทุกเช้า 08:30) สรุปเช้าของ Claude อ่านจากแท็บนี้

## บอททำงานอย่างไร
1. **webhook (`doPost`)** — รับ event จาก LINE: รูป/ไฟล์ (pdf, jpg, png) ดึงไฟล์เต็มจาก LINE แล้วเซฟเข้า inbox ทันที + เพิ่มแถวคิว; ข้อความเก็บลงแท็บข้อความ
2. **`processQueue` ทุก 5 นาที** — อ่านคิวรอบละ 8 ไฟล์: Gemini แยกชนิดเอกสาร/เลขที่/วันที่/ยอด → ย้ายไฟล์เข้าโฟลเดอร์เดือน → ลงทะเบียนบิล (`applyDoc_`)
3. **`dailyJob` 08:30** — สร้างรายการตามใบกำกับ (`buildFollowups_`); วันที่ 1 ร่างสรุปยอดรุ่งเรืองของเดือนก่อนจากข้อความในกลุ่มทั้งเดือน แล้ว push หาคุณอ้อย

### กติกาจับคู่
| เจ้า | บิลเกิดจาก | จับคู่ใบกำกับด้วย |
|---|---|---|
| เจสตาร์ (`JSTAR`) | ใบส่งสินค้า / รายงานบิลค้าง / ใบเสร็จรับเงิน (เลข IV…) | เลขในช่อง "อ้างอิง" ของใบกำกับ = เลขใบส่งสินค้า และยอดเท่ากัน |
| ป.รุ่งโรจน์ (`PRR`) | ใบเสนอราคา QT… → สลิป (ยอดเท่ากัน) | ยอดเท่ากัน เลือกบิลที่จ่ายแล้วและวันที่ใกล้สุด |
| รุ่งเรือง (`RRL`) | สลิปโอนสิ้นเดือนหรือต้นเดือนถัดไป (1 บิลต่อเดือน · สลิปวันที่ 1–10 นับเป็นยอดเดือนก่อน ถ้าเดือนก่อนยังไม่เคลียร์) | ยอดโอน |
| ยางเทรลเลอร์ (`YTL`) / อื่นๆ | ใบกำกับ (มาพร้อมของ) | ไม่ต้องจับคู่ |

- เจสตาร์ใช้เลข `IV…` ทั้งใบส่งสินค้าและใบกำกับ และเลขซ้ำกันได้ → แยกด้วยหัวกระดาษ ("กำกับ" + VAT > 0) ไม่ใช่เลข (`docKind_`)
- ยอดต่างเกิน 1 บาท / ใบกำกับไม่อ้างบิล / ใบกำกับ 2 เลข → ขึ้นคอลัมน์ **รอตรวจ** ไม่จับคู่เอง
- เอกสารของลูกค้ารายอื่นที่หลงมาในกลุ่มเจสตาร์ (รหัสลูกค้าไม่ใช่ `C-P124`) ถูกข้าม
- เอกสารซ้ำ (เจ้า + ชนิด + เลขที่เดียวกัน) ไม่ลงเบิ้ล

### กติกาทวง (`buildFollowups_`)
| เจ้า | ขึ้นรายการเมื่อ |
|---|---|
| เจสตาร์ | ทุกวันจันทร์ + วันสุดท้ายของเดือน: บิลที่ยังไม่มีใบกำกับทั้งหมด · 4 วันสุดท้าย: บิลช่วงนั้นที่ยังไม่มีใบกำกับ (เสี่ยงลงวันที่ข้ามเดือน) · ตั้งแต่วันที่ 25: ขอรายงานบิลค้าง จนกว่าจะมีรายงานลงวันที่ ≥ 25 |
| ป.รุ่งโรจน์ / รุ่งเรือง | โอนแล้วครบ 2 วันยังไม่มีใบกำกับ ซ้ำทุก 2 วัน (นับวันปฏิทิน) |
| รุ่งเรือง | สรุปยอดสิ้นเดือน (คุณอ้อยยืนยัน 26 พ.ย. 2569) → บอทร่างสรุปยอดเดือนก่อน 08:30 วันที่ 1 · ใบกำกับออกเดือนถัดไป ลงวันที่เดือนถัดไป = ภาษีซื้อเดือนถัดไป ไม่ถือว่าข้ามเดือน และไม่อยู่ในรายการ "ค้างจากเดือนก่อน" · เดือนถัดไปวันที่ 2, 4, 6, 8, 10 ถ้ายังไม่มีสลิปของยอดเดือนก่อน เตือน |
| ทุกเจ้า | วันที่ 1–5: บิลเดือนก่อนที่ยังไม่มีใบกำกับ · ทุกวัน: รายการรอตรวจ |

### สิ่งที่คนทำในชีท
- **ได้ตัวจริง**: ติ๊กคอลัมน์ O ในแท็บทะเบียนบิลซื้อ (บอทไม่ทับ)
- **ยกเลิกบิล** (เช่น ใบเสนอราคาที่ไม่ได้ซื้อ): พิมพ์ `ยกเลิก` ในคอลัมน์สถานะ (บอทไม่ทับ และเลิกตาม)
- **เคลียร์รอตรวจ**: ลบข้อความในคอลัมน์รอตรวจหลังตรวจแล้ว
- บอท**ไม่เขียน**แท็บ ซื้อ/ขาย/ค่าใช้จ่าย — การลงบัญชีทำตอนปิดบัญชีตามเดิม

## ติดตั้ง (ครั้งแรก)
1. **LINE OA**: สร้าง "YH Purchase" → OA Manager → ตั้งค่า → ตั้งค่าการตอบกลับ: ปิดข้อความทักทาย + ปิดข้อความตอบกลับอัตโนมัติ, เปิด Webhook
2. **LINE Developers** (channel Messaging API ของ YH Purchase): เปิด "Allow bot to join group chats" · ออก Channel access token (long-lived)
3. **Apps Script**: script.google.com → New project ชื่อ "YH Purchase Bot" → วาง `Code.gs` ทั้งไฟล์
4. **Script properties**: `LINE_TOKEN`, `WEBHOOK_KEY` (ตั้งเองยาว ๆ), `GEMINI_API_KEY` (ใช้คีย์เดียวกับระบบจดบัญชีได้), `OI_USER_ID` (ใส่ทีหลัง)
5. รันฟังก์ชัน **`setup`** 1 ครั้ง (กดอนุญาตสิทธิ์) → ได้ 5 แท็บ + ตั้งเวลา 2 งาน · รัน `testConfig` และ `testGemini` ดูผลใน Execution log
6. **Deploy** → New deployment → Web app → Execute as: Me, Who has access: Anyone → คัดลอก URL
7. LINE Developers → Webhook URL = `<URL>?k=<WEBHOOK_KEY>` → Use webhook: เปิด
8. **ทดสอบในกลุ่มของเราเองก่อน**: เชิญ YH Purchase เข้ากลุ่มทดลอง → แท็บ บอท-ตั้งค่า จะมีแถวใหม่ → ใส่ซัพพลายเออร์ (เช่น `PRR`) + ติ๊กเปิดใช้ → ส่งรูปเอกสาร 1 ใบ → ภายใน ~5 นาที แท็บ บอท-คิว ต้องเป็น `DONE` และไฟล์อยู่ในโฟลเดอร์เดือน
9. ผ่านแล้วค่อยเชิญเข้ากลุ่มจริง (คนเชิญต้องแอด YH Purchase เป็นเพื่อนก่อน) แล้วตั้งค่าแถวของกลุ่มนั้น: เจสตาร์ = `JSTAR` / keyword · ป.รุ่งโรจน์ = `PRR` / keyword · รุ่งเรือง = `RRL` / **all** (ต้องเก็บทุกข้อความเพื่อร่างสรุปยอด)
10. คุณอ้อยทักบอท 1 ครั้ง → คัดลอก userId จากแท็บ บอท-ตั้งค่า ไปใส่ `OI_USER_ID` (แถวของคุณอ้อย/Thipwon ตั้งซัพพลายเออร์ = `AUTO` + เปิดใช้ เพื่อ forward เอกสารเข้าแชท 1:1 ได้)

## ข้อจำกัดที่รู้
- Apps Script อ่าน header ไม่ได้ → ตรวจลายเซ็น `X-Line-Signature` ไม่ได้ ใช้ `?k=WEBHOOK_KEY` ใน URL แทน + รับเฉพาะแหล่งที่ติ๊กเปิดใช้
- ปุ่ม Verify ใน LINE Developers อาจขึ้น error เพราะ Apps Script ตอบแบบ redirect — ให้ดูผลจริงจากแท็บ บอท-คิว (ยังไม่ได้ทดสอบ ดู `claude/line-oa-rules.md` ข้อ 3)
- บอทเห็นเฉพาะข้อความหลังเข้ากลุ่ม และไม่เห็นแชทส่วนตัวระหว่างคนกับคน (ต้อง forward เข้าแชทกับบอท)
- 1 ไฟล์ = 1 เอกสาร: PDF สแกนรวมหลายใบ (เช่น สแกนตัวจริงทั้งเดือน) บอทอ่านได้ใบเดียว → ให้ Claude อ่านตอนปิดบัญชีแทน
- ไฟล์เกิน 50 MB ดึงจาก LINE ไม่ได้
- ปีผิด: วันที่ที่เก่ากว่าวันรับไฟล์เกิน 180 วันหรือเป็นวันอนาคต บอทลองเปลี่ยนเป็นปีของวันรับ (`fixYear_`) แล้วเขียนในผลจับคู่ว่า "แก้ปีที่อ่านผิด"
- ร่างสรุปยอดรุ่งเรืองมาจาก AI อ่านข้อความอิสระ พลาดได้ → คุณอ้อยต้องตรวจก่อนส่งทุกครั้ง
- Gemini free tier มีเพดานต่อนาที/ต่อวัน ถ้าเต็ม ไฟล์จะค้าง `NEW` แล้วรอบถัดไปอ่านต่อเอง
